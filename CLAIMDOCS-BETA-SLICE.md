# One bounded public-beta slice

Proposed follow-up to **`INCLUDE_AFTER_BOUNDED_REPAIR`**. No implementation or Constellation enrollment is authorized by this plan. Keep the frozen candidate unchanged. Goal: one source-free portable corpus demonstrating claims, evidence, unresolved obligations and explicit history to an operator without Cartography.

## Deliverable boundary

One files/schema/CLI/library reconciliation slice, using three sanitized fixtures: retention with an open successor; observation restored without service-repair proof; scoped acceptance strengthened later without erasing unearned claims. No private production host labels, credentials, private evidence links, source checkout requirement for ordinary inspection, new service, tracker write, model, notification transport, executor or Workbench redesign.

1. Preserve the existing configurable graph and charter distinctions. Reconcile a versioned portable data envelope and actual adequacy fields; reject duplicate identities rather than file-order substitution. Explicitly decide that finite owner-scoped obligation enumeration is permitted, distinct from the reserved speculative corpus analysis.
2. Add a bounded publication/readout gate that consumes exact validation results/scope and strict declared admission. Bind input/evidence/source identities; mark unbound/unhashable/age/closure limitations. Strong render cannot silently claim checks absent from its bound report. Repeated fixed inputs/date give exact output correspondence.
3. Add the minimal orthogonal obligation facet: explicit inventory, lifecycle decision references, all-unresolved enumeration/coverage receipt, one-way dated tracker snapshot and closure conflict. No external network connector is necessary; validate an exported snapshot and keep the authoritative reference. No ranking, automatic reconciliation or general workflow engine.
4. Preserve immutable historical snapshots and explicit current selection/supersession. The same bundle must reproduce its historical readout, prominently labeled historical. A deleted source branch cannot erase retained origin/decision/evidence identity; unavailable support remains visible.
5. Supply a small offline CLI/report and operator guide with attached evidence. Forcing relevance uses an explicit recorded match/nonmatch/unknown witness, not a new rule service. Keep a library projection suitable for later lane/incident/Workbench adapters, without implementing those hooks now. Resolve loopback server wording/binding or omit `serve` from the beta surface; CDN UI is optional and must not be needed for inspection.

If this cannot remain one bounded offline slice, stop and split/defer it; do not invent a platform to justify inclusion. Closure-freshness inference, code/test execution plugins, authenticated signatures, general incident UI, manpage templating and automatic tracker synchronization remain separate future work.

## Acceptance criteria

An independent reviewer must inspect exact source/package/corpus hashes and distinguish model assertions from installed behavior. Shared vectors and focused tests must demonstrate:

- Newer weaker basis cannot replace older qualified evidence through duplicate IDs or recency. Conflicts remain explicit.
- Old unresolved obligations remain in complete scoped results; unknown/unavailable coverage cannot render “none outstanding.”
- Missing basis refuses strong current claims or labels unsupported; no false service failure/clear is inferred.
- Closed tracker item without closure proof remains semantically unresolved; stale imported status is dated/unknown.
- Duplicate identities, supersession cycles/dangling successors and overlapping unresolved transfer scopes refuse or report a conflict.
- Stale cited evidence, unchecked dependency closure and unbound source generation remain visibly different.
- Retained obligations/history survive branch removal and cache omission; the tested enrolled startup projection invokes enumeration without Continuity.
- Historical output is reproducible and labeled; current selection never erases its evidence or transfers acceptance silently.
- A forcing match is auditable against exact rule/evidence, including nonmatch/unknown; it requests review, not effects or automatic paging.
- Fresh public-user fixture works from files/package + guide alone, no Cartography, hidden helper, model or daemon. All nine assessment questions have bounded answers, including unknowns.

The finite lifecycle/coverage model and shared vectors are part of acceptance, not a later TODO. Test the actual validator/readout correspondence; a passing model alone does not qualify implementation. Install/package identity and license/dependency closure must be explicit before Constellation consumes it. None of these new acceptance criteria has passed in the current engine.

One accepted portable slice may justify a later thin read-only Constellation adapter under its own integration scope. It does not become part of BC1 by proximity. External trackers retain scheduling authority; Cartography remains the program corpus/policy map; Continuity remains contextual cache. The implementation owner, resource envelope and acceptance owner must be named at dispatch. The present spike closes with conditional recommendation and durable successor tracking, not an implementation claim.
